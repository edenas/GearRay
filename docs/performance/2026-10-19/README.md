# GearRay performance investigation — 2026-10-19

Stage 1 investigation, performed independently. No commit, push, or production implementation. The pre-existing dirty working tree is the baseline, not HEAD. Read [HANDOFF_TO_ASTRA.md](HANDOFF_TO_ASTRA.md) before proposing implementation.

## Decision

The emulator's display refresh is not the engine's update rate. **Actual Emulicious execution demonstrates many VBlanks between input/simulation updates.** A separate standard emulator process independently observed 15, 13, and 19 VBlank IRQs across three ordinary authored-scene input intervals. The scripted, sprite-free static fixture still needs about nine display periods per update. Camera-changing frames are considerably more expensive. This is a demonstrated CPU/workload and scheduling problem, with additional control quantization; it is not adequately explained by LCD persistence.

The largest changing-view cost is the software compositor. Raycasting alone also exceeds a 59,736-T-state display period in the tested static view. Consequently a few arithmetic or banking improvements cannot establish 60 gameplay updates/s. There is room for useful improvement, including an experimental exact bitplane-loop change, but a responsive redesign must address both work volume and simulation scheduling. No original-hardware result or physical button-to-photon measurement is claimed.

## Evidence and interpretation

**MEASURED** means actual generated bytes/instructions or actual emulator execution, with method identified. **PROVEN** means a stated mathematical/control-flow result. **OBSERVED** means directly demonstrated behavior. **INFERRED** and **HYPOTHESIS** retain their uncertainty. Static instruction counts are never executed-cycle counts. Microbenchmark IRQ-disabled results are never whole-frame measurements.

The [evidence directory](evidence/) contains raw frame/stage CSVs, all scenario RAM fixtures and inputs, emulator/toolchain hashes, validator logs, call/helper/function/RAM/module censuses, source identity, experiment sources, generated Z80 and ROMs. [baseline-inputs.zip](evidence/baseline-inputs.zip) freezes the 262 baseline source/asset/document inputs; [baseline-build.zip](evidence/baseline-build.zip) freezes compiler/linker outputs and the exact ROM; [experiments.zip](evidence/experiments.zip) preserves all four alternatives. The emulator and toolchain remain external dependencies, identified by hashes. No findings depend solely on an inaccessible temporary log.

The repository-wide inventory covers 14,092 accessible non-Git files at its early capture, including retained build evidence and newly generated audit ROM output; it is not a claim that every stale build artifact is production. Linker membership defines the 57 current application/generated objects. Historical build artifacts are indexed rather than silently treated as current executable inputs.

Supplement: [COMPILED_MICROBENCHMARKS.md](COMPILED_MICROBENCHMARKS.md) separates per-entity projection, safe transfer and camera-call measurements from complete-update results. [bank-occupancy.csv](evidence/bank-occupancy.csv), [ram-complete.csv](evidence/ram-complete.csv) and [experiment-code-metrics.csv](evidence/experiment-code-metrics.csv) provide the full resource comparisons.

[External reference boundaries](EXTERNAL_REFERENCE_NOTES.md) distinguish primary documentation/interface research from local measurements. [Completion checks](evidence/completion.json) verify required documents, archive integrity, local links, source preservation, Release profiler exclusion and an exact eight-interval replay. [changed-files.csv](evidence/changed-files.csv) enumerates investigation additions and generated outputs; [final-status.txt](evidence/final-status.txt) preserves the complete dirty-tree context. No production input changed and no commit/push occurred.
